# Лабораторная работа № 10 — «Интерактивные дашборды»

## ВАЖНО: как запустить без установки библиотек

**Для просмотра дашборда не нужны Python, pip, Streamlit, Plotly, Node.js или интернет.**

1. Распакуйте весь архив `GoT_Battles_Lab10.zip` в одну папку.
2. Откройте папку `GoT_Battles_Dashboard`.
3. Дважды щелкните `ЗАПУСТИТЬ_ДАШБОРД.bat`.
4. Если Windows спросит разрешение, разрешите открыть файл в браузере. Также можно открыть `index.html` вручную через Chrome, Edge или Firefox.

Данные встроены прямо в `index.html`, поэтому не перемещайте этот файл отдельно от папки проекта и не удаляйте его содержимое. Страница работает локально и не загружает данные на внешние сайты.

## Что находится в дашборде

- **Смертность персонажей:** фильтры по году смерти, принадлежности, книге, Gender и Nobility; KPI; распределение по годам и книгам; кольцевая диаграмма по принадлежностям; линия, тепловая карта, точечная диаграмма и таблица.
- **Прогнозы:** фильтры actual, pred, дом, культура, male и isNoble; расчет доли совпадений actual/pred; распределения классов и alive; гистограмма, scatter plot и таблица.
- **Сражения:** фильтры по году, региону, типу сражения, первому атакующему дому, исходу и месту; KPI; распределения по годам/регионам/типам, накопительная линия, матрица «регион × тип», scatter plot численности сторон и таблица.
- **Методика:** описание состава CSV, преобразований, ограничений данных и технической реализации.
- Каскадные фильтры обновляют доступные значения последующих списков; все графики и KPI обновляются при изменении выборки. Есть кнопка сброса фильтров и экспорт текущей выборки в CSV.

## Технологии

Дашборд реализован на HTML5, CSS3 и чистом JavaScript. Визуализации строятся на SVG без внешних библиотек. Это автономная статическая страница, которая открывается напрямую как `file://.../index.html`.

## Структура

```text
GoT_Battles_Dashboard/
├── index.html                         # готовый автономный дашборд
├── dashboard_template.html            # шаблон страницы
├── ЗАПУСТИТЬ_ДАШБОРД.bat                # запуск двойным щелчком
├── ПЕРЕСОЗДАТЬ_ДАШБОРД.bat              # пересборка index.html (необязательно)
├── data/
│   ├── raw/                            # три исходных CSV
│   └── processed/data_quality.json     # результаты проверки исходных данных
├── scripts/build_dashboard.py         # сборка HTML, только стандартная библиотека
├── tests/test_build_dashboard.py       # проверки без сторонних пакетов
├── reports/                            # отчет DOCX и PDF
├── figures/                             # иллюстрации к отчету
├── requirements.txt                    # сторонние пакеты не требуются
└── .github/workflows/check.yml          # проверки в GitHub Actions
```

## Необязательная пересборка HTML после изменения CSV

Нужен только установленный Python 3. Запустите `ПЕРЕСОЗДАТЬ_ДАШБОРД.bat` или выполните в CMD из папки проекта:

```bat
py -3 scripts\build_dashboard.py
```

После выполнения снова откройте `index.html`. Для обычного просмотра пересборка не требуется.

## Проверки проекта

Проверки используют только стандартную библиотеку Python:

```bat
py -3 -m unittest discover -s tests -v
```

## Особенности и ограничения данных

- В `character-deaths.csv` 917 записей и 13 столбцов. Поле метода смерти отсутствует, поэтому фильтр по типу смерти не заявляется.
- В `character-predictions.csv` 1 946 записей и 33 столбца. `actual` и `pred` показываются как исходные двоичные коды 0/1; вычисляется доля совпадений только по строкам с обоими заполненными значениями.
- В `battles.csv` 38 записей и 25 столбцов. Есть регион и место, но нет географических координат; карта не строится.
- Номер книги не подменяется номером сезона.
- Пропуски не заменяются фиктивными нулями.
- Совпадение персонажей из двух таблиц по имени само по себе не гарантирует тождество записей.

## Публикация в GitHub

Выполните команды из корневой папки проекта после создания пустого репозитория на GitHub:

```bat
git init
git add .
git commit -m "Rebuild standalone GoT interactive dashboard"
git branch -M main
git remote add origin https://github.com/<USERNAME>/<REPOSITORY>.git
git push -u origin main
```

Замените `<USERNAME>` и `<REPOSITORY>` на свои значения. Не добавляйте `.venv`, личные токены и пароли.

## Отчет

Готовые файлы отчета находятся в `reports/` (DOCX и PDF). Для открытия и сдачи дополнительных библиотек не требуется. Скрипт `scripts/generate_report.py` — вспомогательный исходный файл для повторной генерации отчета; для него отдельно нужны `python-docx` и `matplotlib`. Это не влияет на запуск дашборда.
